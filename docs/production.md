# Jagat 正式接入与已知限制

## 当前交付边界

V3可完整演示绑定、照顾、成长品质、估值、地图寻宠、互动、商城小屋、奖励申请、剧情和三种秘密终局。它是一个本机模拟：A/B同设备；UI投影隐藏未授权正文和投票，但底层LocalStorage仍存有双方数据。不可将其视为身份验证、加密私信、反作弊或支付系统。

- 正式后端、数据库、WebSocket和多设备同步：未实现。
- 登录/GPS/Jagat地图/广告/支付/真实奖励：未接入，仅Adapter边界。
- 原创SVG和CSS为主要视觉；Emoji的具体字形取决于系统。
- 虚拟地图中地点访问是轻量模拟；本地邀请链接无法让另一台设备加入同一房间。
- 自然日计算工具按绑定时间起每24小时计算，正式活动应确认采用24小时还是固定业务时区日界，再由服务端统一实现。
- 品质使用周期内累计、每日上限，不衰减；未来若改为滚动窗口需版本化规则与历史重算，不能静默改旧记录。
- Demo跳日期可以回退，品质和奖励事件不会回滚。这是演示功能，不是正式活动资格。
- 数据面板是单浏览器事件次数，不是独立用户统计；没有远程采集、归因平台或真实外部分享成功检测。
- 未来信件以演示日解锁；正式生产必须使用服务端时间。Demo不要输入敏感信息。
- 本机跨标签会读取较新版本，但不提供跨进程事务锁；正式交易与投票需要数据库事务。
- 实际iOS/Android设备、WebView桥接、分享唤起和下载行为需真机回归。

## 建议服务端接口

`GameAPI`已有 `get / execute / reset`接口形状，`HttpGameAPI`是可替换客户端，尚无对应服务端。

| 接口域    | 最小正式能力                             | 强制约束                                                            |
| --------- | ---------------------------------------- | ------------------------------------------------------------------- |
| 会话      | JagatBridge.authenticate、会话刷新       | 服务端验证Jagat签名；角色从会话推导，不信任请求role                 |
| Couple    | 创建、邀请、接受、双方确认、解除、删除   | 邀请哈希/过期/一次性使用、防重复绑定、成员权限                      |
| Game      | GET /game、POST /commands                | 版本校验、幂等键、服务端时间、事务提交、限流                        |
| Growth    | 追加事件、每日限额、品质、估值、日历     | 客户端不提交已计算奖励/品质/钱包；规则版本化                        |
| Sync      | 订阅房间版本变更                         | 按情侣鉴权，断线恢复，不广播私信或未揭晓选票                        |
| Letters   | 发送、撤回、接收、到期解锁               | 独立成员ACL；到期前不得返回正文；撤回销毁正文                       |
| Votes     | 提交、状态、揭晓、新轮次                 | 独立私有表；只返回是否提交；双人完成后原子揭晓；幂等/防重放         |
| Map       | MapAdapter                               | 用户主动授权后才使用必要位置；Demo不请求定位                        |
| Payment   | SKU下单、签名回调、退款                  | 真实货币为整数分；客户端不得发星星币；服务器验单                    |
| Reward    | 独立RewardPolicy/Eligibility/Application | 与模拟估值分离；审核/名额/风控/财务控制，不按消费或广告提高现金奖励 |
| Ads       | showRewardedAd、showNativeAd             | 验证回调；仅装饰，私信/投票/揭晓不插广告                            |
| Share     | JagatBridge.share                        | 主动确认、最小信息、双方结局同意；只确认系统真正提供的结果          |
| Analytics | 匿名事件接收、去重、来源归因             | 禁止私信正文、照片、精确定位；按授权/保留期采集                     |

## 奖励与隐私

`MockRewardService`与`mockRewardPolicy`仅模拟资格和申请。真实发放前必须单独制定活动规则、资格计算、名额及审核流。当前不存在真实收购承诺、现金奖励到账或充值能力。模拟审核通过也不会触发转账。

解除绑定清除本地私人信件、需要偏好和未揭晓选票，保留成长记录供本机回看；完整Demo重置清除V3存档。正式版需要双方各自的数据导出/删除、保留期、访问撤销以及共享历史处理政策。

正式上线前还需完成适用法律、平台政策及未成年人保护要求审查。此文档为接入工程说明，不代表已经完成审查或获得上线资质。
